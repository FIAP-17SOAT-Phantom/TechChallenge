1. Login e autorizacao no Swagger

POST /api/auth/login

Cole no corpo (ajuste a senha para a que voce definiu em ADMIN_PASSWORD):

{
  "email": "admin@oficina.local",
  "senha": "Admin@123456"
}

A resposta traz o token. No Swagger, clique em Authorize (cadeado no topo) e cole apenas o token (sem escrever "Bearer"). A partir dai, todas as rotas protegidas ja vao autenticadas.

O e-mail do admin padrao e admin@oficina.local no Compose e admin@oficina.com em alguns ambientes de teste. Use o que estiver configurado no seu .env / Secret.

6. Aprovacao de orcamento (API obrigatoria 3)

Ha duas formas. A exigida pela fase e o webhook externo.

6.1. Via webhook externo (com assinatura HMAC)

POST /api/webhooks/orcamentos/{orcamentoId}/resposta

Este endpoint exige o header X-Webhook-Signature, calculado com o WEBHOOK_ORCAMENTO_SECRET. Nao da para montar a assinatura na mao — use o script PowerShell da secao 9 para gerar o corpo e o header prontos.

Corpo (exemplo; o externalEventId e a assinatura saem do script):

{
  "externalEventId": "evt-0001",
  "resposta": "Aprovado",
  "timestampUnix": 1762150000
}

No Swagger, cole esse corpo e preencha o campo de header X-Webhook-Signature com o valor sha256=... gerado pelo script. Valores aceitos em resposta: Aprovado ou Rejeitado.

Ao aprovar, a OS passa para EmExecucao e o estoque e reservado. Reenviar o mesmo externalEventId e idempotente (a segunda chamada retorna repetido: true e nao reserva de novo).

6.2. Via cliente autenticado (alternativa)

Primeiro crie um usuario com role Cliente:

POST /api/auth/usuarios (como Admin)

{
  "email": "bruno.03fr@gmail.com",
  "role": "Cliente",
  "clienteId": "COLE_AQUI_O_CLIENTE_ID"
}

A resposta traz uma senha temporaria. Faca login com esse usuario, troque a senha em POST /api/auth/alterar-senha, logue de novo e então chame:

PATCH /api/orcamentos/{orcamentoId}/aprovar (ou /rejeitar) — sem corpo.

7. Execucao, finalizacao e entrega

PATCH /api/ordens-de-servico/{ordemDeServicoId}/servicos/{servicoId}/executar
PATCH /api/ordens-de-servico/{ordemDeServicoId}/finalizar
PATCH /api/ordens-de-servico/{ordemDeServicoId}/entregar

Nenhum tem corpo. Execute na ordem. Ao finalizar, as reservas de estoque sao consumidas.

8. Listagem de OS (API obrigatoria 4)

GET /api/ordens-de-servico?pagina=1&tamanhoPagina=20

Retorna as OS ordenadas por prioridade (Em Execucao > Aguardando Aprovacao > Em Diagnostico > Recebida), mais antigas primeiro, excluindo logicamente as Finalizadas e Entregues. Para comprovar a exclusao logica, consulte uma OS entregue por id: ela ainda existe em GET /api/ordens-de-servico/{id}, mas nao aparece na listagem.

9. Script para o webhook (gerar corpo + assinatura)

O corpo canonico assinado e: externalEventId \n timestampUnix \n orcamentoId \n RESPOSTA (RESPOSTA em maiusculas). Rode este PowerShell, informando o orcamentoId e o mesmo WEBHOOK_ORCAMENTO_SECRET do seu .env:

# gera-webhook.ps1
param(
  [Parameter(Mandatory=$true)][string]$OrcamentoId,
  [Parameter(Mandatory=$true)][string]$Secret,
  [ValidateSet("Aprovado","Rejeitado")][string]$Resposta = "Aprovado"
)
$externalEventId = "evt-" + [guid]::NewGuid().ToString("N").Substring(0,8)
$ts = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
$payload = "$externalEventId`n$ts`n$OrcamentoId`n$($Resposta.ToUpperInvariant())"
$hmac = [System.Security.Cryptography.HMACSHA256]::new([Text.Encoding]::UTF8.GetBytes($Secret))
$hash = $hmac.ComputeHash([Text.Encoding]::UTF8.GetBytes($payload))
$sig  = ([BitConverter]::ToString($hash) -replace '-','').ToLower()

Write-Host "`n--- Corpo (cole no Swagger) ---"
@{ externalEventId=$externalEventId; resposta=$Resposta; timestampUnix=$ts } | ConvertTo-Json
Write-Host "`n--- Header X-Webhook-Signature ---"
Write-Host "sha256=$sig"

O script ja esta salvo na raiz do projeto como gera-webhook.ps1. Uso (Windows PowerShell):

powershell -ExecutionPolicy Bypass -File ./gera-webhook.ps1 `
  -OrcamentoId "COLE_O_ORCAMENTO_ID" `
  -Secret "SEU_WEBHOOK_SECRET"

O -ExecutionPolicy Bypass e necessario porque o sistema bloqueia scripts por padrao. Ele imprime o JSON do corpo e o header sha256=..., prontos para colar no Swagger. O timestamp vale por 300s (tolerancia padrao), entao use logo apos gerar.

11. Verificar a notificacao por e-mail

Cada mudanca de status gera um e-mail para o e-mail do cliente da OS. Com o provider padrao Log, o envio e apenas registrado no log do Worker:

docker compose logs -f worker
Para enviar e-mail de verdade para bruno.03fr@gmail.com, configure no .env: EMAIL_PROVIDER=Resend e RESEND_API_KEY=sua-chave (conta gratuita em resend.com). Sem isso, o e-mail so aparece no log.
